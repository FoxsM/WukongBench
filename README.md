# WukongBench

Консольная утилита на C# (.NET 8), которая полностью автоматически делает два прохода
**Black Myth: Wukong Benchmark Tool** (Steam, AppID `3132990`) — CPU-тест и GPU-тест —
и выдаёт отчёт с характеристиками ПК, результатами и использованными настройками.

## Быстрый старт

Требования: Windows 10/11, Steam (запущен и залогинен), установленный Black Myth: Wukong Benchmark Tool,
[.NET 8 SDK](https://dotnet.microsoft.com/download/dotnet/8.0).

> Если бенчмарк ни разу не запускался — запустите его один раз вручную и закройте:
> так он создаст `GameUserSettings.ini`.

```powershell
git clone <ссылка на репозиторий>
cd WukongBench
dotnet run -c Release --project src/WukongBench
```

или собрать один exe:

```powershell
dotnet publish src/WukongBench -c Release -r win-x64 --self-contained false -o out
out\WukongBench.exe
```

Параметры (необязательные):

| Параметр | Назначение |
|---|---|
| `--game-dir "<папка>"` | папка бенчмарка, если автопоиск не нашёл её |
| `--config <файл>` | другой `appsettings.json` |
| `--cpu-only` / `--gpu-only` | выполнить только один проход |

Во время теста **не трогайте мышь и клавиатуру** и не переключайте окна — утилита сама нажимает кнопку запуска в меню.

## Что происходит при запуске

1. **Поиск бенчмарка** — путь Steam из реестра → все библиотеки из `libraryfolders.vdf` → `appmanifest_3132990.acf`.
2. **Резервная копия** `b1\Saved\Config\Windows\GameUserSettings.ini` (в конце восстанавливается, в т.ч. при Ctrl+C и ошибках).
3. **Сбор характеристик ПК** через WMI и реестр: CPU (ядра/потоки/частота/L3), GPU (VRAM из реестра драйвера — WMI обрезает до 4 ГБ, версия драйвера), RAM (объём, модули, частота), плата, ОС, монитор, диск, план питания.
4. Для каждого прохода:
   - запись настроек в `GameUserSettings.ini` согласованно в двух местах, которые читает игра:
     секция `[/Script/GSGameSettings.GSGameUserSettings]` (разрешение, режим окна, VSync и строка
     `UISettingData=(("Key", "Value"),...)` со значениями меню) и `[ScalabilityGroups]` (`sg.*` = значение меню − 1);
   - запуск `steam.exe -applaunch 3132990 -dx12`, ожидание процесса `b1-Win64-Shipping` и его окна;
   - через `MenuLoadDelaySeconds` выполняется сценарий `StartActions` через `SendInput`: Enter на экране «Нажмите любую кнопку» →
     клик мышью по «Тест быстродействия» (главное меню реагирует только на мышь) → Enter + клик по «Подтвердить».
     Если через `StartRetryMinutes` результата нет, сценарий повторяется;
   - ожидание нового файла в `%TEMP%\b1\BenchMarkHistory\Tool\` — его бенчмарк пишет по окончании прогона. Файл считается готовым, когда размер перестал меняться и он парсится как JSON;
   - закрытие бенчмарка и пауза-«остывание».
5. **Разбор результата**: `FPSAvg`, `FPSMin`, `FPSMax`, `FPS95` + все прочие поля (фактические настройки, версия, модели CPU/GPU).
   Из покадровых `Records` (`FrameRate`, `CPUFrameTime`, `GPUFrameTime`, `VideoMemoryUsage`) утилита считает
   **1% low / 0.1% low**, средний frametime, отдельно CPU- и GPU-frametime (видно, что было узким местом) и расход VRAM.
   **Проверка**: фактические настройки из JSON (`ScreenResolution`, `QualityLevel`, `ImageQuality`, `Rtx`, `InsertFrame`)
   сверяются с заданными, расхождения выводятся в консоль и отчёт.
6. **Отчёт** — в консоль и в `results/<дата_время>/`:

```
results/2026-10-06_15-30-00/
├── report.md                      ← читаемый отчёт (таблицы)
├── report.json                    ← то же в машинном виде
├── GameUserSettings.original.ini  ← бэкап
├── cpu/  benchmark_raw.json, GameUserSettings.applied.ini
└── gpu/  benchmark_raw.json, GameUserSettings.applied.ini
```

## Пример результата

Полный отчёт: [docs/sample-report.md](docs/sample-report.md) (i5-11400F, RTX 3060 8 ГБ, 16 ГБ RAM).

| Тест | Разрешение | Avg FPS | Min | FPS95 | 1% low | CPU frametime | GPU frametime |
|---|---|---|---|---|---|---|---|
| CPU | 1280×720, 50%, Low, RT off | **87** | 52 | 79 | 74.5 | 6.8 мс | 10.2 мс |
| GPU | 2560×1440, 100%, Cinematic, Full RT Very High | **16** | 11 | 14 | 14.0 | 8.1 мс | 58.6 мс |

В GPU-тесте время кадра GPU (58.6 мс) в ~7 раз больше времени кадра CPU (8.1 мс): FPS полностью определяется видеокартой.
В CPU-тесте нагрузка на GPU снижена почти в 6 раз (10.2 мс против 58.6 мс), а FPS выросла в 5.4 раза.

## Выбор настроек

### CPU-тест — убрать видеокарту из уравнения

| Настройка | Значение | Почему |
|---|---|---|
| Разрешение | 1280×720 | минимум пикселей при сохранении нормальной работы меню/HUD |
| Масштаб рендера | 50% | внутреннее разрешение ≈ 640×360 — в ~36 раз меньше пикселей, чем в 4K; пиксельная работа GPU почти исчезает |
| Пресет | Low (все `sg.*` = 0) | тени, GI (Lumen), отражения, эффекты, пост-обработка — в основном нагрузка на GPU |
| Ray Tracing | выкл | RT — самая тяжёлая для GPU функция |
| Frame Generation (`InsertFrame`) | выкл | сгенерированные кадры почти удваивают «FPS» и не отражают работу CPU |
| VSync / лимит FPS | выкл | иначе FPS упрётся в частоту монитора, а не в процессор |
| Полноэкранный режим | эксклюзивный | без накладных расходов композитора Windows |

Логика, расчёт кадра, анимации, физика, подготовка draw calls и стриминг остаются теми же,
поэтому FPS ограничивается процессором. Проверить: в `report.md` в полях результата видна загрузка GPU —
в CPU-тесте она должна быть заметно ниже 95–99%.

### GPU-тест — максимальная нагрузка на видеокарту

| Настройка | Значение | Почему |
|---|---|---|
| Разрешение | нативное разрешение монитора (определяется автоматически) | максимум пикселей, доступный в полноэкранном режиме |
| Масштаб рендера | 100% | рендер в полном разрешении, без апскейла |
| Пресет | Cinematic (все `sg.*` = 4) | максимальные тени, Lumen GI, отражения, растительность, эффекты, текстуры |
| Дальность прорисовки | Cinematic | больше геометрии в кадре |
| Full Ray Tracing | вкл, уровень Very High | самая тяжёлая нагрузка на RT-ядра и шейдеры |
| Frame Generation | выкл | FG снижает реальную нагрузку на кадр и искусственно поднимает FPS |
| VSync / лимит FPS | выкл | GPU должен работать без ограничений |

Если видеокарта не поддерживает аппаратный RT, игра проигнорирует его — либо поставьте `"RayTracing": false` в `appsettings.json`.

## Настройка (`appsettings.json`)

Все профили и тайминги вынесены в конфиг, перекомпилировать ничего не нужно:

- `Cpu` / `Gpu` — `Width`, `Height` (0 = нативное), `ResolutionScale`, `Quality` (0 Low … 4 Cinematic), `ViewDistance`, `RayTracing`, `RayTracingLevel` (0 Low … 3 Very High), `UiSettingOverrides` (любые ключи `UISettingData`, значения как в меню);
- `MenuLoadDelaySeconds` — сколько ждать загрузку меню перед нажатием (на HDD увеличьте);
- `StartActions` — сценарий старта: `Key:Enter`, `Click:x,y` (доли окна 0..1, напр. `Click:0.11,0.463`), `Wait:мс`;
- `StartRetryMinutes` — через сколько минут без результата повторить сценарий;
- `LaunchMode` — `Steam` (по умолчанию) или `Direct`;
- `ResultDirs` — где искать файлы результатов.

## Структура кода

| Файл | Ответственность |
|---|---|
| `Program.cs` | сценарий: поиск → бэкап → 2 прохода → восстановление → отчёт |
| `SteamLocator.cs` | поиск Steam и папки бенчмарка |
| `IniFile.cs` | построчный редактор UE-ini (сохраняет порядок и неизвестные ключи) |
| `SettingsApplier.cs` | применение профиля теста |
| `BenchmarkRunner.cs` | запуск, нажатие старта, ожидание результата, закрытие |
| `InputSender.cs`, `NativeMethods.cs` | WinAPI: фокус окна, `SendInput`, режим дисплея |
| `ResultParser.cs` | разбор JSON результата, расчёт 1%/0.1% low |
| `SystemInfo.cs` | характеристики ПК (WMI + реестр) |
| `ReportWriter.cs` | консоль, `report.md`, `report.json` |

## Если что-то пошло не так

- **Тест не стартовал** — увеличьте `MenuLoadDelaySeconds`; при другом расположении кнопок поправьте координаты в `StartActions`. Можно и нажать кнопку вручную — утилита дождётся результата.
- **Настройки не применились** — утилита сама пишет расхождения («Проверка: …»). Сравните `GameUserSettings.applied.ini` с полями `benchmark_raw.json`.
- Исходные настройки бенчмарка всегда лежат в `results/.../GameUserSettings.original.ini`.
